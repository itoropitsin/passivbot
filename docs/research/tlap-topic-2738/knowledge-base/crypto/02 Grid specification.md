# Спецификация криптовалютной сетки

Назад: [[00 MOC — Crypto bot]] · Риск: [[03 Risk controls]] · Общая идея: [[../02 Grid construction]]

## Обязательные поля

### Инструмент

- биржа и рынок;
- символ;
- spot или futures;
- тип контракта;
- Long, Short или оба направления;
- режим one-way или hedge;
- isolated или cross margin;
- залоговая валюта.

### Геометрия

- фактическая цена первого исполнения;
- направление;
- список плановых уровней;
- способ расчёта расстояния;
- число уровней;
- объём каждого уровня;
- правило округления;
- правило пропуска уровня;
- максимум номинала;
- цель закрытия корзины.

### Расходы и риск

- комиссия открытия и закрытия;
- ожидаемое финансирование;
- ожидаемое проскальзывание;
- требуемая начальная маржа;
- поддерживаемая маржа;
- расстояние до ликвидации;
- денежный стоп;
- портфельный лимит.

## Состояние

Одной сетке нужен журнал состояния:

1. planned — уровни рассчитаны;
2. armed — первый вход разрешён;
3. opened — первое исполнение получено;
4. expanding — добавляются следующие уровни;
5. partial — часть заявки или позиции исполнена;
6. closing — есть заявка на закрытие;
7. closed — позиция закрыта и результат зафиксирован;
8. paused — новые действия запрещены;
9. emergency — требуется аварийное действие;
10. reconciled — состояние сверено с биржей после перезапуска.

После каждого события состояние должно быть повторяемым из журнала. Если биржа сообщает неизвестный остаток, сетка не должна молча создавать следующий ордер.

## Счёт корзины

Для каждого фактически исполненного ордера считать:

- количество;
- среднюю цену;
- комиссию;
- funding;
- реализованный и нереализованный результат;
- ликвидационный запас;
- вклад в итоговый TP;
- плановый и фактический уровень.

Средняя цена только по заявленному объёму недостаточна при частичном исполнении.

## Варианты геометрии

Тестировать как разные гипотезы:

- равномерный шаг;
- шаг, нормированный на волатильность;
- расширение шага по мере глубины;
- ограниченное наращивание объёма;
- ступенчатый объём без бесконечного множителя;
- отдельные Long и Short;
- режим только сопровождения после определённой глубины.

Каждый вариант должен иметь свой риск-бюджет. Нельзя менять форму сетки в live, чтобы скрыть плохой исторический результат, без нового идентификатора версии.

## Запреты

Система должна запретить:

- заявку ниже минимального номинала;
- выход за лимит номинала;
- новый уровень при недостаточном запасе до ликвидации;
- повторную заявку после таймаута без сверки;
- смешение ручной позиции и автоматической сетки;
- продолжение после неизвестного состояния;
- реинвест выше установленного потолка.
