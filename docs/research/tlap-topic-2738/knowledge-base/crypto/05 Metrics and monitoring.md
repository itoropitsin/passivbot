# Показатели и мониторинг крипто-бота

Назад: [[00 MOC — Crypto bot]] · Риск: [[03 Risk controls]] · Тесты: [[04 Backtest and walk-forward]]

## Показатели результата

- чистый результат после комиссий и funding;
- результат фиксированным риском;
- результат реинвеста;
- результат по каждому символу;
- результат по Long и Short;
- доходность на рабочий капитал и на полный резерв;
- количество закрытых сеток;
- средняя прибыль и убыток одной сетки.

## Показатели риска

- просадка по балансу и эквити;
- максимальная и 95-й процентиль просадки;
- суммарная маржа;
- запас до ликвидации;
- максимальный номинал;
- максимальная глубина;
- время в позиции;
- время восстановления;
- количество стопов;
- одновременно плохие сетки.

## Показатели исполнения

- задержка сигнала;
- задержка заявки;
- задержка исполнения;
- плановая и фактическая цена;
- проскальзывание;
- доля частичного исполнения;
- отмены;
- повторные заявки;
- ошибки API;
- расхождение состояния бота и биржи.

## Рабочие пороги

Для каждого сета заранее заполнить:

| Показатель | Нормальный | Стресс | Аварийный порог | Факт |
|---|---:|---:|---:|---:|
| Просадка |  |  |  |  |
| Запас до ликвидации |  |  |  |  |
| Маржа |  |  |  |  |
| Проскальзывание |  |  |  |  |
| Ошибки API |  |  |  |  |
| Доля частичных исполнений |  |  |  |  |
| Время восстановления |  |  |  |  |

Аварийный порог должен приводить к действию: запретить новые сетки, перейти в reduce-only, закрыть риск или запросить ручное решение.

## Мониторинг событий

Сохранять события:

- создана сетка;
- первый вход;
- новый уровень;
- частичное исполнение;
- пропуск;
- пересчёт TP;
- превышение риска;
- изменение funding;
- ошибка API;
- потеря связи;
- восстановление;
- ручное действие;
- остановка и причина.

График капитала без журнала событий недостаточен: он не объясняет, была ли просадка рыночной, технической или вызвана неверным восстановлением.

## Ежедневная проверка

- позиции на бирже совпадают с состоянием бота;
- нет неизвестных заявок;
- запас до ликвидации выше порога;
- комиссии и funding поступают в расчёт;
- новые сетки разрешены только при нормальном состоянии;
- резерв и лимит риска не превышены;
- последний replay и live-лог не расходятся по формату.
